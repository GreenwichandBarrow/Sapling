Rule: each `RECOMMEND … → YES / NO / DISCUSS` resolves exactly one decision. If a caveat needs Kay's input (e.g. "Process payroll is normally Monday recurring — move it anyway?"), it must be its own numbered RECOMMEND, not a parenthetical inside the main one.

**Why:** 2026-05-19 — I batched a "move 11 Mon→Tue items" RECOMMEND with a parenthetical note about payroll being recurring-Monday. Kay's "no" meant no to the payroll caveat; I read it as no to the whole batch and stood down. She had to re-prompt to recover the 10 moves I should have executed.

**How to apply:**
- One ask, one resolution. If two things need a decision, write two items.
- A note in the body that says "Note: X is unusual" reads as a flag, but if it changes what YES means, it's a second decision — break it out.
- When Kay's NO seems narrower than the ask scope, re-read the framing before standing down. Ambiguous NO + scoped caveat = likely "no to the caveat, yes to the rest" — but the fix is to never frame it that way.
